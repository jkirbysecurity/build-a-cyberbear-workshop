# 3.3 - Terraforming S3 Buckets

### Objectives

The objective of this lesson is to build a well-configured and hardened **S3 Bucket** for your CyberBear range using Terraform.


## Challenges

### Challenge 1: Add an S3 Bucket to Range

1.  Visit the following Terraform resource documentation for building S3 Buckets, review the docs and learn how to use the resources.

    - [Resource: aws_s3_bucket](http://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket)

2. Copy the `aws_s3_bucket` resource code block to your template in a new section named **S3 BUCKETS**.  Add this section after the **CYBER BEARS**, but before the **OUTPUTS**.

    - This bucket will be used for storing logs
    - **Notice** the `force_destroy` attribute set to true.  Normally, you cannot delete a bucket unless it is empty.  However, in training/dev/test, you want to be able to force destroy your buckets regardless of if there are objects in them or not.
    - **Notice** the `${random_string.uid.result}` at the end of the bucket attribute.  As we know, S3 buckets are global resources that requiring globally unique names since the names are used in the URL's for the endpoint.  Here we are using the `random_string` resource to append the end of the bucket name to ensure uniqueness.
    - **:warning: Important Note:** This is a basic bucket and is not secure or well configured.  The remaining challenges in this lesson will be adding additional configurations to harden the bucket.

            ############################################################################################
            # S3 BUCKETS
            ############################################################################################
            # Log bucket
            resource "aws_s3_bucket" "log_bucket" {
              bucket = "${local.name_prefix}-log-bucket-${random_string.uid.result}" # bucket name

              force_destroy = true # only use during testing
            }

3. Add outputs for the S3 Bucket under the Hosts sections

        S3 Bucket
        --------------------------------------------------------------------------------------
        ${aws_s3_bucket.log_bucket.id}

4. Deploy Your CyberBear Range and Review Your New S3 Bucket

    - Run `terraform plan` -- **Notice** the S3 bucket shows in the plan

    - Run `terraform apply` -- When it asks to confirm, type `yes`

    - Review new resource in the console
      - Open AWS management console
      - In the top search box, search `S3`
      - Select your S3 bucket
      - View details
        - Verify basic bucket


### Challenge 2: Configuring and Hardening S3

**Note:** Visit the resource docs to learn more about each as you use them

1. Add [Resource: aws_s3_bucket_ownership_controls](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_ownership_controls)

        # Bucket Ownership
        resource "aws_s3_bucket_ownership_controls" "log_bucket_owner" {
          bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to
          rule {
            object_ownership = "BucketOwnerEnforced" # Defines bucket/object ownership
          }
        }

2. Add controls to **block all public access** via: [Resource: aws_s3_bucket_public_access_block](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_public_access_block)

        # S3 Public Access Block
        # This should be default configuration for all buckets - required for security.  Open up as needed for specific use case.
        resource "aws_s3_bucket_public_access_block" "log_bucket_block_public_access" {
          bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to

          block_public_acls       = true
          block_public_policy     = true
          ignore_public_acls      = true
          restrict_public_buckets = true
        }

3. Add **S3 KMS Encryption** for your bucket 

    - (*This is Optional, and not required.  But I wanted to show you how to do it. -- **KMS IS NOT FREE***)
    - **Note:** Default encryption is SSE-S3, but may not meet your business/compliance requirements since there is not key management or auditing. 
    - Create [Resource: aws_kms_key](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/kms_key) to use for your bucket
    - **Note:** You can add this block anywhere.  I think it makes sense to add to the **S3 BUCKETS** section with the rest of the bucket code.
    - **Note:** All KMS keys must have a key policy. If a key policy is not specified, AWS gives the KMS key a default key policy that gives all principals in the owning account unlimited access to all KMS operations for the key. This default key policy effectively delegates all access control to IAM policies and KMS grants.
    - **Note:** An [AWS KMS key alias](https://docs.aws.amazon.com/kms/latest/developerguide/kms-alias.html) is **a friendly display name for a cryptographic key in AWS Key Management Service**. It let's you reference a key using an easy-to-remember name like `alias/my-key` instead of a long, random key ID or ARN.

            #######################################
            # KMS Keys
            #######################################
            # Create KMS key for encrypting bucket
            resource "aws_kms_key" "bucket_key" {
              description             = "This key is used to encrypt bucket objects"
              enable_key_rotation     = true # Enables auto key rotation
              deletion_window_in_days = 7 # 7-30 days
            }

            resource "aws_kms_alias" "bucket_key_alias" {
              name          = "alias/bucket-key"
              target_key_id = aws_kms_key.bucket_key.key_id
            }

    - Next, add the **KMS Encryption** configuration to your S3 bucket via the [Resource: aws_s3_bucket_server_side_encryption_configuration](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_server_side_encryption_configuration)
    - **Notice** the `kms_master_key_id` is for the bucket key we previously created
    - **Notice** the `sse_algorithm` is set to `"aws_kms"`

            # Enables KMS encryption
            resource "aws_s3_bucket_server_side_encryption_configuration" "log_bucket_encryption" {
              bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to

              rule {
                apply_server_side_encryption_by_default {
                  kms_master_key_id = aws_kms_key.bucket_key.arn # KMS key association  
                  sse_algorithm     = "aws:kms" # Server-side encryption algorithm
                }

              bucket_key_enabled = true # When KMS encryption is used to encrypt new objects in this bucket, the bucket key reduces encryption costs by lowering calls to AWS KMS
              }
            }
    
4. Enable **Bucket Versioning** using the [Resource: aws_s3_bucket_versioning](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_versioning)

        # Enables bucket versioning
        resource "aws_s3_bucket_versioning" "log_bucket_versioning" {
          bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to
          
          versioning_configuration {
            status = "Enabled"
          }
        }

5. Enable **Server Access Logging** using [Resource: aws_s3_bucket_logging](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_logging)

    - **Note:** This example is for demonstration purposes.  Normally you would send your access logs to another bucket. -- In an AWS Organization, you would send your logs to a global log bucket.

          # Enables bucket access logging
          resource "aws_s3_bucket_logging" "log_bucket_logging" {
            bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to

            target_bucket = aws_s3_bucket.log_bucket.id # Target bucket where you are sending logs to
            target_prefix = "access-logs/" # Send logs to folder with the target prefix
          }

6. Add a **force SSL/TLS** bucket policy to force all traffic to the bucket to be encrypted.  This policy effectively **denies all** traffic that is not encrypted.

    - Use [Resource: aws_s3_bucket_policy](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_policy) to add this policy

          # Force SSL to access bucket
          resource "aws_s3_bucket_policy" "log_force_ssl_bucket_policy" {
            bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to
          
            policy = jsonencode({
              Version = "2012-10-17"
              Statement = [{
                Sid       = "ForceSSLOnlyAccess"
                Effect    = "Deny"
                Principal = "*"
                Action    = "s3:*"
                Resource = [
                  "${aws_s3_bucket.log_bucket.arn}/*",
                  "${aws_s3_bucket.log_bucket.arn}"
                ],
                Condition = {
                  Bool = {
                    "aws:SecureTransport" = "false"
                  }
                }
              }]
            })
          }

7. Use the [Resource: aws_s3_bucket_lifecycle_configuration](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket_lifecycle_configuration) to create and set a **Bucket Lifecycle Configuration** for your objects

    - **Review** the various transition options and expiration so that you know what you are configuring

          # Enables and sets bucket data lifecycle configuration
          resource "aws_s3_bucket_lifecycle_configuration" "log_bucket_config" {
            bucket = aws_s3_bucket.log_bucket.id # Bucket to associate to

            rule {
              id = "logs"

              status = "Enabled" # Enabled or Disabled

              abort_incomplete_multipart_upload {
                days_after_initiation = 1 # number
              }

              expiration {
                days = 365 # integer > 0
              }

              transition {
                days          = 30 # integer >= 0
                storage_class = "STANDARD_IA" # string/enum, one of GLACIER, STANDARD_IA, ONEZONE_IA, INTELLIGENT_TIERING, DEEP_ARCHIVE, GLACIER_IR.
              }

              transition {
                days          = 60 # integer >= 0
                storage_class = "GLACIER" # string/enum, one of GLACIER, STANDARD_IA, ONEZONE_IA, INTELLIGENT_TIERING, DEEP_ARCHIVE, GLACIER_IR.
              }

              noncurrent_version_expiration {
                newer_noncurrent_versions = 3 # integer > 0
                noncurrent_days           = 60 # integer >= 0
              }

              noncurrent_version_transition {
                newer_noncurrent_versions = 3 # integer >= 0
                noncurrent_days           = 30 # integer >= 0
                storage_class             = "GLACIER" # string/enum, one of GLACIER, STANDARD_IA, ONEZONE_IA, INTELLIGENT_TIERING, DEEP_ARCHIVE, GLACIER_IR.
              }
            }
          }

    - Notice the plan shows you are only adding new resources.  Nothing is being deleted or changed.

2. Run `terraform apply` -- When it asks to confirm, type `yes`

3. Review new bucket configurations in the console
    - Select your S3 bucket
    - View details
      - Verify the configurations you set in the code
