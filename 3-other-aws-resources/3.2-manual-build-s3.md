# 3.2 - Manually Building S3 Buckets

### Objectives

The objective of this lesson is to walk through manually building and configuring **S3 Buckets** in the console for learning how they are built and comparison to using code.


## Challenges

### Challenge 1: Manually Build an S3 Bucket

1. In the top search bar of the management console, search `s3` and select the **S3** service

    ![S3 - Search](/3-other-aws-resources/images/1-s3-search.png)

    ---

2. Select **Create bucket**

    - If this is your first time using S3, you will get the service landing page

        ![S3 - Create Bucket - Landing Page](/3-other-aws-resources/images/2-s3-landing-page.png)

        ---

    - If you have used S3 before, you will be on the **Buckets** main page

        ![S3 - Create Bucket - Main Page](/3-other-aws-resources/images/3-s3-bucket-page.png)

        ---

3. Configure bucket

    - Make sure **General purpose** is selected
    - Give your bucket a name
        - **Note:** Bucket names have a global name space on the internet and are used in URL's.  This requires them to be uniquely named throughout all the world.
        - I have prepended my manual bucket with my initials, and appended it with the last for digits of my phone number.

        ![S3 - Create Bucket - Name](/3-other-aws-resources/images/4-s3-name.png)

        ---

    - Scroll down, **notice** the **Object Ownership** is "Bucket owner enforced"
    - Ensure **Block *all* public access** is checked in the **Block Public Access for this bucket** section
        - This is a default setting and ensures all public access is blocked, forcing builders to be explicit about what they open up to the public.
        - **Side note:** It used to be not long ago that this setting was not default.  But after MANY very public data breaches/leakages finding that buckets were simply just configured "open", leading to S3 and by extension AWS being branded as "insecure and unsafe", AWS changed their default configurations in response to public and Big Corporate backlash. 

        ![S3 - Create Bucket - Block Public Access](/3-other-aws-resources/images/5-s3-block-public-access.png)

        ---

    - Scroll down, **notice** that **Bucket Versioning** is disabled.  [S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/versioning-workflows.html) is a data protection feature that allows you to keep, retrieve, and restore every version of every object stored in your bucket. Once enabled, it prevents data loss from accidental overwrites or permanent deletions.  We do not need this for our purposes, so leave it disabled.

        ![S3 - Create Bucket - Versioning](/3-other-aws-resources/images/6-s3-versioning.png)

        ---

    - Scroll down, **notice** that **Default encryption** is selected as **SSE-S3**
        - **Special Note:** **SSE-KMS** is more secure and likely required for any regulatory requirements your company may have, however, for the purposes of this course we will stay with the default encryption.
        - **Another Side Note:** Again, not long ago, default encryption for S3 did not use to be a thing for AWS.  But similar to default blocking all public access, AWS changed their ways and did right for their customers. -- Google stories about these things if you are interested in learning more about cloud security/breach history.
    - If all your configurations look good, select **Create bucket**

        ![S3 - Create Bucket - Encryption & Create](/3-other-aws-resources/images/7-s3-encryption-create.png)

        ---
    
    - Once created, you will be dropped into your bucket


### Challenge 2: Review Bucket Configuration and Options

While we will not be adding any additional configurations to this bucket, it is important to get to know many of things you can do to further harden and configure your bucket, and where the configurations are located.

1. Review **Objects** tab

    - This will be empty since you just created the bucket and have not uploaded any objects
    - This is also where you can manually upload objects to your bucket

        ![S3 - Review - Objects](/3-other-aws-resources/images/8-s3-objects.png)

        ---

2. Pivot to the **Properties** tab

    - Copy the **bucket ARN** and save for later    
    - **Observe** that **Bucket Versioning** is disabled

        ![S3 - Review - Properties - Versioning](/3-other-aws-resources/images/9-s3-properties-versioning.png)

        ---

    - Scroll down to the **Default Encryption** section
        - **Review** that the **Encryption type** is set to **Server-side encryption with Amazon S3 managed keys (SSE-S3)**

        ![S3 - Review - Properties - Encryption](/3-other-aws-resources/images/10-s3-properties-encryption.png)

        ---

    - Continue scrolling down to the **Server access logging** section
        - **Note** that this is disabled as well
        - **Server access logs** are a critical logging service in production.  S3 buckets are servers behind the scenes.  You need to log who/what is accessing your data for support and possible security incidents.

        ![S3 - Review - Properties - Logging](/3-other-aws-resources/images/11-s3-properties-logging.png)

        ---

    - Scroll down the rest of the way to the **Statice website hosting** section
        - **S3 static website hosting** hosting is disabled by default
        - **Note:** S3 is an excellent option for hosting static websites.  This is where you would configure this option.  For proper security, you will pair this with **Amazon CloudFront**, which is AWS's global Content Distribution Network (CDN), so that website users connect to the CDN and NOT directly to the bucket. --> Using CloudFront with signed cookies or signed URL's keeps your bucket private, while allowing public access to content.  

        ![S3 - Review - Properties - Static Website Hosting](/3-other-aws-resources/images/12-s3-properties-website-hosting.png)

        ---

3. Pivot to the **Permissions** tab

    - Observe **Block *all* public access** is configured **On**

        ![S3 - Review - Permissions - Block Public Access](/3-other-aws-resources/images/13-s3-permissions-block-access.png)

        ---

    - Scroll down to the **Bucket policy** section
        - While we are not configuring anything here, this is where you would add bucket policies.  You will see a policy for enforcing encrypted traffic here later.

        ![S3 - Review - Permissions - Bucket Policy](/3-other-aws-resources/images/14-s3-permissions-bucket-policy.png)

        ---

    - Scroll down to the **Bucket Ownership** section
        - **Observe** that **Bucket owner enforced**
        - Also observer default bucket **Access Control List (ACL)**
            - **Notice** the **Bucket owner (your AWS account)** is the only **Grantee** that has **List, Read, or Write** permissions.

        ![S3 - Review - Permissions - Bucket Owner & ACLs](/3-other-aws-resources/images/15-s3-permissions-bucket-ownership.png)

4. Pivot to the **Management** tab

    - Observe **Lifecycle configuration**
    - This is where you can configure lifecycle management rules to automatically move your objects to more cost effective tiered storage options, archiving, and eventually automatically deleting if you would like.  Reference your corporate Data Retention Policies for setting this.
    - **Notice** this is empty.  This is expected since you do not have any **Lifecycle rules** configured.

        ![S3 - Review - Management](/3-other-aws-resources/images/16-s3-management.png)

        ---


**-- End Of Exercise --**
