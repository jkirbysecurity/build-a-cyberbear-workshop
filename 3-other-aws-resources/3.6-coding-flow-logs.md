# 3.6 - Terraforming Flow Logs

### Objectives

The objective of this lesson is to add **VPC Flow Logs** for your CyberBear Range using Terraform.


## Challenges

### Challenge 1: Add VPC Flow Logs to Range

1. Visit the [Terraform Resource: aws_flow_log](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/flow_log) resource documentation, review the docs and learn how to use the resource.

2. Copy the `aws_flow_log` resource code block to your template under the route table associations in the **NETWORK** section

    - Set the `log_destination` to **arn** of S3 bucket you previously created
    - Set the `log_destination_type` to `"s3"`
    - Set the `traffic_type` to `"ALL"`
    - Set the `vpc_id` to your vpc so that it is associated to and capturing all VPC flow log traffic
    - **Notice** the `depends_on` equals our S3 log bucket?  If we were deploying the range for the first time, we would need for the destination bucket to be created before the flow logs so that there are no issues.

            # Create VPC Flow Log
            resource "aws_flow_log" "flow_logs" {
            log_destination      = # Log destination
            log_destination_type = # Log destination type
            traffic_type         = # Type of traffic to filter
            vpc_id               = # VPC to associate flow logs with

            tags = {
                Name = "${local.name_prefix}-flow-logs"
            }

            depends_on = [aws_s3_bucket.log_bucket]
            }


### Challenge 2: Redeploy Your CyberBear Range & Review Your VPC Flow Logs

1. Run `terraform plan` and review the additions to your plan
    - Again, **notice** the plan shows you are only adding new resources.  Nothing is being deleted or changed.

2. Run `terraform apply` -- When it asks to confirm, type `yes`

3. Review new resources in the console
    - In the top search box, search `VPC`
    - Select your range VPC
    - View details
        - See Flow Log and configuration details


**-- End Of Exercise --**
