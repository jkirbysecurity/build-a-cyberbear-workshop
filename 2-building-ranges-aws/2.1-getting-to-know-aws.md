# 2.1 - Getting To Know AWS

### Objectives

The objectives of this lesson are to get familiar with some of the most common **AWS Infrastructure as a Service (IaaS) resources and services**.

## Common AWS IaaS 

In general, it is a good practice to learn how services work and how to build them manually in the console before coding them.  -- What all is required to build the resource or service?  And, what are all the flags and switches that can be configured?

Then codify what you’ve built, and compare the manual build to the coded build. -- Do they match?  Did you miss or forget anything?

I’m going to give you a quick and dirty, high-level overview the initial/basic AWS services you need to know about before we get building in case you are not versed in AWS.  These are the resources and services we are initially going to be building and coding in this workshop.

As always, read the attached docs for more information about each of these services.

- **Amazon VPC (Virtual Private Cloud)** – gives you full control over your virtual networking environment, including resource placement, connectivity, logging and security.  The VPC is your private computing environment in AWS.

    - **Regions & Availability Zones (AZ)** – At the time of this recording, the AWS Global Infrastructure spans 123 Availability Zones within 39 Geographic Regions.
        - AWS has the concept of a Region, which is a physical geographical location around the world where they cluster data centers. Each AWS Region consists of a minimum of three, isolated, and physically separate Availability Zones (AZ) within that geographic area.
        - An Availability Zone is a logical grouping of one or more discrete data centers with redundant power, networking, and connectivity in an AWS Region.
        - In the US, for example, there are 4 Regions – `us-east-1` and `us-east-2`, `us-west`, and `us-central`.
            - There are also 2 Regions in Canada and 1 in Mexico to round out the Regions in North America.
        - The concept of Regions and Availability Zones give customers the ability to operate high performing, highly resilient and secure systems and services.
        - A VPC exists within a Region.  And a subnet exist within Availability Zones.
    
    - **Subnets** – In networking, a subnet (or subnetwork) is a network inside a network.
        - Subnets make networks more efficient → Through subnetting, network traffic can travel a shorter distance without passing through unnecessary routers to reach its destination.
        - **Important note:** A subnet is a range of IP addresses.  They DO NOT overlap with other subnets on the same network.
        - A subnet must reside entirely within one Availability Zone. 
    
    - **Route Tables** – A route table serves as the traffic controller for your VPC. Each route table contains a set of rules, called routes, that determine where network traffic from your subnet or gateway is directed.
    
    - **Internet Gateway** – An internet gateway enables resources in your public subnets to connect to the internet if the resource has a public IP address.
    
    - **NAT Gateway (Network Address Translation)** – Allows instances in a private subnet to connect to services outside your VPC and/or the internet, but external services can not initiate a connection with those instances. 
        - *We are not going to be building these in this workshop, but they are important to know about.*

- **EC2 Instances (Elastic Compute Cloud)** – These are your virtual servers in AWS.  They consist of several configuration components
    - **AMI (Amazon Machine Image)** – This is the image/operating system for your instance, and may consist of additional preconfigured software.
    - **EBS (Elastic Block Storage)** – Is for running your operating system and on-instance storage.
    - **Instance Type** – Configuration of CPUs, RAM, and network performance.

- **Security Groups** – Act as a virtual firewall for your EC2 instances to control incoming and outgoing traffic. 
    - Security Groups by default do not allow any traffic.  In other words, they “DENY ALL”.  You must configure “ALLOW” rules to allow traffic.
    - Security Groups are stateful, meaning if something goes comes in or goes out, it will allow the corresponding response traffic through.

### :tipping_hand_person: Side Notes & Pro Tips:

AWS Regions come pre-configured with “default” VPCs.  And VPCs come pre-configured with “default” Security Groups.  AWS does this to make it easy for customers to get started and up & running.  That said, it is best practice NOT to use these “default” VPCs and Security Groups.  Instead, restrict them so others cannot use them, and create custom VPCs and Security Groups specific to your needs.  This ensures configurations are deliberate for your specific business use case.

- You would not use default passwords or guest accounts.  This is basically the same concept.
