# 2.5 - Build Manually First -- EC2 Instances

### Objectives

The objective of this lesson is to walk through manually building and configuring an **EC2 Instance** and **Security Group** in the console for learning how they are built and comparison to using code.


### Challenge 1: Manually Build an EC2 Instance and Security Group

1. Back in the AWS Management Console, search `ec2` in the top search bar and select the **EC2** service

    ![EC2 Search](/2-building-ranges-aws/images/15-aws-ec2-search.png)

    ---

2. Select **Launch instance** in the middle of the page to launch the instance wizard

    ![EC2 Launch Instance](/2-building-ranges-aws/images/16-aws-ec2-dashboard.png)

    ---

3. Configure new instance

    - In the **Name and tags** section, give your instance the name `manual-web-server`
    - In the **Application and OS Images (Amazon Machine Image)** --> **Quick Start** section
        - Select **Amazon Linux**
            - Review the **Amazon Machine Image (AMI)** and **Description** sections to learn more about the AMI

            ![EC2 Launch - Name & AMI](/2-building-ranges-aws/images/17-aws-launch-ec2-1.png)

            ---

    - **Note:** the **Username** for this AMI is `ec2-user`.  While we are not connecting directly to this instance during this exercise, you could if you wanted and this is the username needed for connecting to the system.
    - Select **t2.micro** for the **Instance type**.  This gives us 1 vCPU and 1 GiB RAM.
        - You will also see the cost/hour if you were paying for this instance type outside of the free tier.
    - Select **Proceed without a key pair (Not recommended)**.  We are not planning to connect to this instance, so we do not really need a key pair.  That said, if you want to connect directly to the system, you will need to create a key pair.

        ![EC2 Launch - Instance Type](/2-building-ranges-aws/images/18-aws-launch-ec2-2.png)

        ---

    - In the **Network settings** section, select **Edit**

        ![EC2 Launch - Network Settings](/2-building-ranges-aws/images/19-aws-launch-ec2-network-settings.png)

        ---

    - In the **VPC - *required*** dropdown, select your custom VPC, **manual-range-vpc**

        ![EC2 Launch - Network Settings - VPC](/2-building-ranges-aws/images/20-aws-launch-ec2-network-settings-vpc.png)

        ---

    - In the **Subnet** dropdown, select one of your public subnets.
    - **Auto-assign public IP** = **Enabled** -- This will allow us to connect to the webserver once built.

        ![EC2 Launch - Network Settings - Assign Public IP](/2-building-ranges-aws/images/21-aws-launch-ec2-network-settings-public-ip.png)

        ---

    - In the **Firewall (security groups)** section, select **Create security group**
    - Set **Security group name** to `manual-sg`
    - Set **Description** to `manual-sg created` and whatever the data/time that pre-fills the box
    - In the **Inbound Security Group Rules** section, create rules for `ssh` and `HTTP` to allow traffic from anywhere
    - Last, observe the **Important Notice** about rules with source `0.0.0.0/0`, and AWS's recommendation to only allow access from known sources
        - **:warning: This is REALLY IMPORTANT.  Please only allow all like this in short lived testing scenarios.**

        ![EC2 Launch - Network Settings - Security Groups](/2-building-ranges-aws/images/22-aws-launch-ec2-network-settings-sg-rules.png)

        ---

    - Select **Advanced details** and scroll down to the bottom
    - Add the **User data** script provided to configure the instance on launch
    - Review **Summary** on the right side
    - If all looks good, select **Launch instance**

        ```
        #!/bin/bash
        sudo yum update -y
        sudo yum install httpd -y
        sudo systemctl start httpd
        sudo systemctl enable httpd
        cd /var/www/html
        echo "<html><h1>Hello Cloud Rangers. Welcome to the manual-web-server webpage.</h1></html>" > index.html
        ```

        ---

        ![EC2 Launch - User Data](/2-building-ranges-aws/images/23-aws-launch-ec2-user-data.png)

        ---

### Challenge 2: Review New EC2 Instance and Security Group

The EC2 instance is now launching.  

1. **Success!!**  Now select **View all instance** to review your new instance

    ![EC2 Review - Details](/2-building-ranges-aws/images/24-aws-view-all-instances.png)

    ---

3. Notice the columns in the **Instances** list.  You can get a quick view of a lot of the details here.  And the columns are customizable in the settings so you can choose what you want to see.

    - Also notice that your new instance is **initializing**.  This may take a minute or two for the instance to be fully launched and the user-data script configurations to complete.

2. Select your new **manual-web-server** to further review **Details** and more in the bottom half of the page

    - Notice the **Public** and **Private IPv4 addresses**
    - Notice the **VPC ID** association reflects that this instance is in your custom **manual-range-vpc**
    - Scroll down to review more details about the instance

        ![EC2 Review - Details](/2-building-ranges-aws/images/25-aws-review-ec2-details.png)

        ---

3. Pivot over to the **Security** tab

    - Notice the **Inbound rules** you configured

        ![EC2 Review - Security](/2-building-ranges-aws/images/26-aws-review-ec2-security.png)

        ---

4. Go back to the **Details** tab and copy the **Public IPv4 address**

    - Open a new browser tab and type `http://` and paste the public ipv4 address
    - You should now see the basic website saying "Hello Cloud Rangers. Welcome to the manual-web-server webpage."
    - If your browser is just spinning and does not open to this message:
        - Either the instance is not fully deployed and give it another minute or two
        - Or you clicked on the **open address** button versus copy/pasting after `http://`.  This one always gets me.
        - Or you type `https://`.  Note this is "HTTP", not "HTTPS".  

            ![EC2 Review - Cloud Ranger Web Site](/2-building-ranges-aws/images/27-manual-web-server.png)

            ---
    
### Challenge 3: Delete EC2 Instance and Security Group

In order to avoid any unnecessary charges, go ahead and terminate/delete the instance.

- **Note:** If you are running a free tier account, the instance is not going to cost you anything.  But it is a good practice to delete the resource when you are done with them so you do not forget about them.  

- **Side note:** If you would like to keep the instance and come back to it at another time, feel free to just **Stop instance** and **Start instance** as needed.

1. Select your instance

    - Select **Instance state**
    - Select **Terminate (delete) instance**

        ![Terminate/Delete EC2](/2-building-ranges-aws/images/28-ec2-terminate.png)

    - Select **Terminate (delete)**

        ![Terminate/Delete EC2 - Confirm](/2-building-ranges-aws/images/29-ec2-terminate-confirm.png)

        ---

2. You should see the instance "shutting down" in the **Instance state** column of the list for a minute or two, and then switch to **Terminated** when down.

    - The instance will eventually be removed from the page after a short time.

    ![EC2 Deleted](/2-building-ranges-aws/images/30-ec2-deleted.png)

---
