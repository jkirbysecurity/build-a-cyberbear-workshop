# 2.10 - Bonus Challenges

### Objectives

The objectives of the bonus challenges is to get more hands on practice and experience building CyberBears to specific configurations.

## Challenges -- Add More CyberBears

### Challenge 1: Ubuntu CyberBear

- Add another CyberBear to your range with the following configurations:
    - name = **Coco Bear**
    - ami = Ubuntu 24
    - associate_public_ip_address = true
    - source_dest_check = false
    - user_data --> update user data script to use `apt` instead of `yum`, and install `apache2` instead of `httpd`
        - also change referenced name in the html code
    - Add OUTPUTS 
        - `locals` --> `output_connect_cheat_sheet`
        - Host details --> public IP, private IP, and ssh command

### Challenge 2: Additional Security Controls

- Add another CyberBear to your range with the following configurations:
    - name = **Pooh Bear**
    - ami = Ubuntu 24
    - associate_public_ip_address = false
    - source_dest_check = false
    - set IMDSv2 (required for security)
    - encrypt the root block (required for security) 
    - user_data --> update user data script to use `apt` instead of `yum`, and install `apache2` instead of `httpd`
        - also change referenced name in the html code
    - Add OUTPUTS 
        - `locals` --> `output_connect_cheat_sheet`
        - Host details --> public IP, private IP, and ssh command


### Challenge 3: Windows CyberBear

- Add another CyberBear to your range with the following configurations:
    - name = **Teddy Bear**
    - ami = Windows Server 2025
    - ami_owner = use the data lookup for Windows
    - instance_type = Windows Server Instance Type
    - root_volume_size = 30
    - associate_public_ip_address = true
    - source_dest_check = false
    - depends_on = subnet module
    - Add OUTPUTS 
        - Host details --> public IP and private IP


### Challenge 4: Deploy Your Additional CyberBears & Review Them

1. Run the following Terraform commands to deploy your additional CyberBears

    - `terraform fmt` to beautify your code
    - `terraform init` to initialize the newly added Terraform modules
    - `terraform plan` and review your plan -- notice Terraform is only adding the additional EC2 Instances
    - Conduct the **Build-A-CyberBear Heart Ceremony** (Optional for fun)
      - Rub your heart with your hands so your cloud has a warm heart
      - Rub your head so your cloud is smart like you
      - Rub your nose so the cloud knows who you are
      - Rub your back so it will always have your back and protect you
      - Shake your hands up high in the air to give your CyberBear Range high hopes to explore and learn great things
      - Jump up and down to get the CyberBear Range heart pumping
      - Give your heart a kiss, close your eyes and make a wish
    - `terraform apply` --> When it asks to confirm, type `yes`

2. Locate the ssh command that was set in the output for the system you would like to connect to and copy/paste it into your terminal.  It should look something like: 

    `ssh -i ./secrets/.pem ubuntu@<public ip>`

    - Once ssh'd in, you should now see a new command line prompt reflecting the `ubuntu@<private ip address>`
    - Run `whoami` to see who you are currently logged in as
    - Run `pwd` to "print working directory".  This is your current location on the system.
    - Feel free to peruse further if you would like
    - Run `exit` to return back to your local system

3. Review new resources in the console.
    - In the top search box, search `EC2`.
    - Select your new CyberBears.
    - View details
        - See the different configuration details


### Challenge 5: Destroy Range


**Tear down** your range so that you do not leave any resources running :money_with_wings: :money_with_wings: :money_with_wings: when you are not using them.

Never forget to destroy your range when you are done playing.

1. From your terminal, run `terraform destroy`

2. When prompted for a response, type `yes` -- this is the only acceptable option
