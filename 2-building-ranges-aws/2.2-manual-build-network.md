# 2.2 - Build Manually First -- The Network

### Objectives

The objectives of this lesson are to walk through manually building and configuring a **custom VPC network** in the AWS management console (aka, "the console") for learning how the resources are built in the console in comparison to code.


## Challenges

### Challenge 1: Manually Build a Custom VPC with Subnets and an Internet Gateway

1. Log into AWS Management Console

    - **Note** the Region you are currently in referenced in the top right of the console
    
2. In the top search bar, search `vpc` and select the **VPC** service

    ![AWS Management Console](/2-building-ranges-aws/images/1-aws-console.png)

    ---

    ![AWS Search VPC](/2-building-ranges-aws/images/2-aws-search-vpc.png)

    ---

3. Select **Create VPC**
    
    ![VPC Dashboard - Create VPC](/2-building-ranges-aws/images/3-aws-vpc-dashboard.png)

    ---

4. Fill out the **Create VPC / VPC settings** wizard to your specifications

    - In the **Resources to create** section, select **VPC and more**
    - In the **Name tag auto-generation** section, name your range `manual-range`
    - Notice the **IPv4 CIDR block** pre-populated
    - Notice the network mappings in the **Preview** section for VPC --> Subnets --> Route Tables --> Network Connections

    ![VPC settings - Naming](/2-building-ranges-aws/images/4-aws-vpc-create1.png)

    ---

    - Set **Number of Availability Zones (AZs)** to **2**
    - Set **Number of public subnets** to **2**
    - Set **Number of private subnets** to **2**
    - Set **NAT gateways** to **None** -- These cost money, they are not needed for this workshop.  
        - ***Side Note:** NAT Gateways are required for instances in private subnets to be able to communicate with the public internet.  We are not putting our instances in private subnets and therefore do not need them.*
    - Notice more of the network mapping in the **Preview** section for VPC --> Subnets --> Route Tables --> Network Connections

    ![VPC settings - AZs and Subnets](/2-building-ranges-aws/images/5-aws-vpc-create2.png)

    ---

    - Set **VPC endpoints** to **None**
    - Notice **DNS options** are both checked to **Enable**
    - When everything looks good --> Select **Create VPC**

    ![VPC settings - Create](/2-building-ranges-aws/images/6-aws-vpc-create3.png)

    ---

5. Watch all the things being created for your new VPC, and select **View VPC** when everything is done being create to review your new `manual-range` VPC.

    ![VPC Create Workflow](/2-building-ranges-aws/images/vpc-create-workflow.png)

    ---


### Challenge 2: Review New Custom VPC

1. From the **VPC dashboard**, select either **Your VPCs** from the left, or **VPCs** in the middle **Resources by Region** section.  They both take you to the same place.

    ![View VPC](/2-building-ranges-aws/images/7-aws-select-vpc.png)

    ---

2. Select **manual-range-vpc** and review the **Details**

    - Notice **DNS hostnames** and **DNS resolution** are both set to **Enabled**
    - Notice the **IPv4 CIDR**

    ![Review VPC Details](/2-building-ranges-aws/images/8-aws-vpc-details.png)

    ---

3. Select the **Resource map** tab

    - **Notice** the **Resource map** is the same as what was previewed when you were building the VPC

    ![Review VPC Resource Map](/2-building-ranges-aws/images/9-aws-vpc-resource-map.png)

    ---

4. Select the **CIDRs** tab

    - Notice the **IPv4 CIDRs**

    ![Review VPC CIDRs](/2-building-ranges-aws/images/10-aws-vpc-cidr.png)

#### Challenge 3: Review Subnets

1. In the left column, select **Subnets** 

    - Select one of your new **manual-range-subnets**
    - Notice the **IPv4 CIDR** column in the Subnets quick view list
    - Review **Details**
        - **IPv4 CIDR** matches above
        - **VPC** association is to your **manual-range-vpc**
        - **Route table** association is to your **manual-range-rtb-public**

    ![Review Subnets](/2-building-ranges-aws/images/11-aws-subnets.png)

    ---

#### Challenge 4: Review Route Tables

1. In the left column, select **Route Tables** and review **Details**

    - Select **manual-range-rtb-public**
    - Notice the **VPC** association is to your **manual-range-vpc**

    ![Review Route Tables Details](/2-building-ranges-aws/images/12-aws-route-tables-details.png)

    ---

2. Select the **Routes** tab

    - Notice the route to the public internet **0.0.0.0/0** is the **Target** **igw** that was created
    - Notice the route to your VPC **10.0.0.0/16** is **local**

    ![Review Route Tables Routes](/2-building-ranges-aws/images/13-aws-route-tables-routes.png)

    ---


#### Challenge 5: Review Internet Gateway

1. In the left column, select **Internet gateways** and review **Details**

    - Select your **manual-range-igw**
    - Notice the **VPC ID** association is to your **manual-range-vpc**

    ![Review Internet Gateway](/2-building-ranges-aws/images/14-aws-iwg.png)

---


**-- End Of Exercise --**
