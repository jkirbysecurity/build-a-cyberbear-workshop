# Who Is IaC For & Why Learn It?

The reasons are plentiful.  And the skills are valuable to a wide variety of audiences.

### Who is IaC For?

- **Software Developers & Engineers**
    - If software developers and engineers can build and manage their own infrastructure, that brings them one step closer to being truly “full-stack."   This not only makes them both more desirable in the market, but also self-sufficient by not having to rely on infrastructure folks to provide the infrastructure for their applications or services to run on.
- **Cloud Developers & Engineers**
    - IaC is core to their job role -- table stakes
- **Architects of all kinds – Enterprise, Infrastructure, Software, Network, Security, etc.**
    - While not necessarily required for doing good architecture, being able to actually build and manage the systems they are designing directly contributes to better, more operationally effective designs.
        - There tends to be friction between engineers and architects when the ones who design things are not responsible for building, implementing or managing them.  So having these skills will reduce that friction.
- **Security Professionals**
    - **Offensive & Defensive / Red Team & Blue Team** 
        - Knowing how to build cloud infrastructure directly supports both of these crafts and operations
    - **Application Security & Cloud Security** – obviously 
        - Learn how things work and how to build securely
        - These skills are critical for code reviews and being able to have conversations with other engineers on a level playing field.
    - **Incident Response & Digital Forensics**
        - It is good to be able to quickly deploy sandbox environments for deep inspections and also for research purposes.
- **Governance, Risk, and Compliance (GRC)**
    - GRC Engineering is the future – governance, audit, and compliance can be codified via policies and automated validation checks
    - Knowing your way around infrastructure code will absolutely help folks in these career paths
- **Network Engineers**
    - Networks are defined with code and are still a big part of building cloud infrastructure
    - IaC should be standard for these folks as well
- **Data Engineers & Scientists**
    - Like software developers and engineers, if data engineers and scientists can build their own infrastructure, they no longer have to wait for or rely on someone else to provide them infrastructure to run their services, whether for R&D or production.


### Why Learn IaC?

- **Automation**
    - Manually building things can not be automated
- **Rapid development and deployment**
- **Consistent**
    - Results are the same every time
- **Reduces human errors**
- **Testable**
    - Code can easily be tested and now your infrastructure can be put through the SDLC and CI/CD pipelines
- **Scalable**
- **Business Continuity & Disaster Recovery folks**
    - IaC allows for very fast recovery during disasters.  Reducing recovery times from days or weeks for manual rebuilds, down to hours when the infrastructure is codified and stored in version control.
    - But if we are being honest with ourselves, rebuilding manually may never fully recover.  And even if you do, it’s not going to be the same.  Configurations will be different since most manual builds are often poorly documented, if at all.


### Added Value

If you are working in the cloud, it’s important to be comfortable with building and managing infrastructure and platforms safely and securely using Infrastructure as Code.  As I mentioned previously, this is how enterprises build, manage and deliver services at scale.

IaC tools and methods allow you to manage infrastructure and platforms like software with configuration files rather than through a graphical user interfaces, and you can put them through software development practices and lifecycles for code reviews, rapid testing, and deployment (DevOps and CI/CD).

And because infrastructure is codified, it allows you to quickly build, change, and manage your infrastructure in a safe, consistent, and repeatable way by defining resource configurations that you can version control, reuse, and share.  →  You want to make a change, just update the code, put it through your CI/CD pipeline, and deploy the change.

Another great advantage of IaC → it will deploy the same every time, no human errors – whether 1 time or 1000’s of times, and the code IS your documentation – in theory, not in real practice – you still need to document your code and projects for ease-of-use and other audiences.  But at a minimum, you always have the code you can read if nothing else exists.
